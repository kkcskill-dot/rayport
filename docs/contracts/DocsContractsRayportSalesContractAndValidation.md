# 대표 도구·마트와 인수 기준

2026-11-08 설계 예제. 모든 이름·수치는 합성 예시다. 실제 테이블과 업무 규칙은 미확인이다. [계약 JSON](../../contracts/tools/ContractsToolsStoreSalesExample.json)은 런타임 설정이 아니라 향후 구현 기준이다.

## 1. 업무 도구: 점포별 순매출 조회

| 항목 | 제안 |
|---|---|
| 도구 ID/버전 | `sales.store_daily` / `1.0.0-draft` |
| 목적 | 허용된 점포의 일·월·연 매출과 같은 기준의 기간 비교 |
| 지표 | 총매출·취소금액·순매출, 통화 KRW, Decimal 금액 |
| 순매출 | 예제에서는 총매출−취소금액. 세금·할인·환율·취소 반영일은 업무 오너 확정 필요 |
| 시간 | Asia/Seoul, 영업일 경계는 점포 마감 기준. 달력 날짜와 같다고 가정하지 않음 |
| 지원 차원 | 영업일·점포. 상품군·고객·채널 미지원 |
| 지원 연산 | 합계, 날짜/점포 그룹, 기간 증감, 순위. 원인 확정/고유 고객 수 미지원 |
| 입력 | 시작일·종료일(끝 제외), 선택 점포 목록, 일/월/년 그룹, 확정/정정 반영 기준 |
| 권한 | 서버의 사용자 점포 범위와 교집합. 범위 밖 점포 지정 시 명시적 거절; 전체 범위와 일부 결과를 혼동하지 않게 함 |
| 출력 | 기간·점포·총매출·취소·순매출, metric_version, data_as_of, complete_through, dataset_version, 범위·통화·정정 기준 |
| 담당 | 업무 오너: 지표/마감 의미. DBA: SQL/계획/예산. 운영자: 공개/롤백 |
| 실행 | 원천 실행은 APIC 등록 도구만. 마트는 동일 계약을 구현하는 별도 어댑터 |

기간 비교는 동일 길이·동일 영업일 기준을 명시한다. 전주 같은 요일, 전월 같은 날짜, 전년 같은 영업일은 서로 다른 비교다. 휴점·신규 점포 포함 여부도 화면에 표시한다.

### 처리 예

질문: “어제 내 점포 순매출을 전주 같은 요일과 비교해 줘.”

1. 질문이 2026-11-08 KST에 작성되었다면 대상 날짜를 11-07과 10-31로 확정한다. 영업일 마감 규칙이 달력과 다르면 그 규칙을 따른다.
2. 서버에서 점포 권한을 확인하고 두 날짜 모두 확보된 마트 버전인지 검사한다.
3. 확정/정정 기준과 통화를 맞춘 후 Decimal 계산으로 증감을 구한다.
4. 숫자·차트와 “정정 반영 기준 / 11-08 06:00 반영” 같은 근거를 표시한다.
5. “상품군별” 후속 질문은 미지원 차원으로 분류해 생성·확장 요청을 제안한다.

예시 API는 `POST /api/v1/tools/sales.store_daily/query`이다. 인증 문맥은 입력 JSON에 넣은 사번으로 대체하지 않는다. 공개 API와 MCP 스키마는 버전 있는 하나의 도구 계약에서 생성한다.

## 2. 실행 경로 선택

실행 전에 도구가 지표·차원·기간·권한·신선도 요구를 지원하는지 검사한다. 다음은 단순 장애 우회 순서가 아니라 **동일 계약을 충족하는 후보 중의 선택 정책**이다.

| 후보 | 선택 조건 | 선택 불가 시 |
|---|---|---|
| 결과 캐시 | 같은 계약·파라미터·권한 범위·정책 버전·데이터 버전·허용 신선도 | 다음 적격 후보 평가 |
| Rayport 마트 | 차원과 기간 커버리지, 데이터 기준, 공개된 스냅샷 버전 일치 | 확보 기간/다음 갱신 안내 |
| 기존 DW/DM | 같은 업무 정의와 권한으로 검증됨, 필요한 최신성 만족 | 갱신·정의 조정 검토 |
| 읽기 복제본/APIC 승인 조회 | 사전 승인된 경로, 복제 지연 허용, 범위·예산 충족 | 예산초과/지연 안내 |
| 운영 원천/APIC 승인 조회 | 별도 허용된 제한 상세/현재 상태 도구에 한함 | 차단·대기·집계 요청 |

과거 장기 집계에 대해 마트/복제본이 실패했다고 운영 원천 경로를 동적으로 만들지 않는다. 실시간 상세 조회와 장기 집계는 도구 계약을 분리하는 것이 초기 구현에 유리하다. 범위 제한·행 제한은 실제 scan 비용의 대체 수단이 아니다.

캐시 키는 tenant, 검증된 권한 범위 fingerprint, authz policy version, tool/metric version, 정규화 입력, dataset version을 포함한다. 권한 변경 시 이전 저장 결과·내보내기도 재검사한다. 권한이 동일한 사용자 간 공유 여부는 별도 정책으로 결정한다.

## 3. 최소 마트 모델

`fact_store_sales_daily`: 한 행은 특정 dataset_version에서 영업일×점포×통화의 실적이다. 통화가 하나라도 grain에 의미를 명시한다.

```text
PK: dataset_version, business_date, store_id, currency
gross_amount decimal(20, 2)
cancel_amount decimal(20, 2)
net_amount decimal(20, 2)
metric_version
source_watermark
source_cutoff_at
quality_status
```

`mart_dataset`: dataset_version, metric_version, 시작/끝 날짜, source_cutoff, complete_through, 준비/검증/공개/폐기 상태. `mart_active_version`은 현재 공개 버전만 가리킨다. 메타데이터 DB와 마트는 소규모 POC에서 PostgreSQL을 공유할 수 있으나 schema·role·connection pool·쿼리 예산을 분리한다. 운영 원천과 같은 인스턴스에 설치하지 않는다.

영업일×점포 집계에 상품군을 나중에 붙여 분배하지 않는다. 해당 분석이 필요하면 원천 또는 검증된 기존 DM에서 다른 grain의 도구를 만들어야 한다. 재고·잔액은 마지막 시점 값이고, 객단가는 합산 매출/합산 거래 수이며, 서로 다른 합산 규칙을 계약에 명시한다.

### 최소 합성 검증 데이터

| 영업일 | 점포 | 총매출 | 취소 | 순매출 |
|---|---|---:|---:|---:|
| 2026-10-31 | S01 | 100,000 | 10,000 | 90,000 |
| 2026-11-07 | S01 | 120,000 | 20,000 | 100,000 |
| 2026-11-07 | S02 | 80,000 | 5,000 | 75,000 |

S01의 11-07 순매출은 100,000원, 전주 동일 요일 대비 +10,000원 / 약 +11.11%다. 두 점포 권한이 있으면 11-07 합계 175,000원이다. S01 권한만 있으면 100,000원이다. 비교 기준이 0이면 증감률을 무한대로 출력하지 않고 `산출 불가(비교 기준 0)`로 표시한다. 데이터 없음과 실적 0은 구분한다.

### 마감·취소 규칙

현재 예제는 취소를 원매출 영업일에 소급 반영하는 가정이다. 취소 발생일 반영이 실제 업무 기준이면 metric version과 적재 규칙을 바꾼다. 원매출일 마감 당시 값과 현재 정정 반영값을 한 지표에 섞지 않는다.

확정 마감 스냅샷은 불변 버전으로 보관하고 현재 정정 집계는 새 버전으로 발행한다. 원천이 과거 마감 결과를 보존하지 않는다면 과거 확정값을 복원한다고 주장할 수 없다. 선택 가능한 기준을 도구 범위에 제한한다.

## 4. 적재·갱신·정정·복구

1. **우선 원천**: 기존 마감 테이블/배치 파일 또는 DW 집계부터 확인한다. 운영계 상세 전체 스캔은 기본 계획에서 제외한다.
2. **최초 적재**: 필요한 기간만 승인된 작업 계획으로 분할한다. 원천별 rate/concurrency/time/IO 예산과 저부하 시간대, 중단·재개 체크포인트를 정한다. 범위 축소로 최신 일부 기간부터 공개 가능하다.
3. **기준 시점**: 여러 API 페이지가 같은 snapshot/마감 cutoff를 공유해야 한다. 확정 실적은 동일 snapshot 또는 불변 마감 자료를 요구한다. 이를 지원하지 않으면 합계 대사 통과만으로 단일 시점 일관성을 증명할 수 없다. 이 경우 업무 오너가 명시 승인한 잠정 자료 계약으로만 제공하고 확정값으로 공개하지 않는다.
4. **증분 갱신**: 가능하면 마감 변경일·수정시각·변경 로그로 영향을 받은 일자/점포를 찾아 그 partition을 재집계한다. 이 키가 없으면 DBA가 승인한 작은 재처리 구간으로 시작하며 그 밖 정정을 자동포착한다고 주장하지 않는다.
5. **늦은 취소/삭제**: 고정 최근 N일 재처리만으로 모든 지연 정정을 보장하지 않는다. 오래된 변경을 찾을 로그/대사 작업이 필요하다. 원천에서 사라진 집계 행은 partition 교체/명시 tombstone으로 제거한다.
6. **중복 방지**: job ID + source watermark + partition + metric version을 idempotency key로 사용한다. 중복 실행이 금액을 누적하지 않도록 replace/upsert한다. 병렬 작업은 lease/fencing token으로 단일 소유권을 보장한다.
7. **검증 후 공개**: 초기 POC는 이전 완성본의 모든 미변경 partition을 서버 내 staging version에 복사하고 변경 partition을 교체해 완전한 새 스냅샷을 구성한다. 원천 전체를 다시 읽지 않는다. 날짜×점포별 커버리지와 명시적인 0/미확보 상태도 포함한다. 규모 확대 시 불변 partition manifest가 전체 버전을 가리키는 방식으로 전환할 수 있다. 행/합계/기간/권한키/원천 대사를 수행한다. 한 트랜잭션으로 active version을 바꿔 부분 갱신을 노출하지 않는다.
8. **실패 복구**: 이전 성공 버전을 유지한다. 신선도 계약을 넘으면 stale임을 표시하고 조회 계약에 따라 제공 또는 차단한다. 재시도는 예산 내 지수 backoff·상한을 적용하고 취소 미확인은 재실행하지 않는다.
9. **캐시 갱신**: dataset version을 키에 포함해 구버전 오염을 막는다. 보관 중인 과거 결과에는 원래 버전과 기준 시각을 유지한다.

CDC는 2단계 선택안이다. 로그 접근·라이선스·보존·DDL·초기 snapshot과 로그 offset의 정합성·중복·삭제·재시작을 검증해야 한다. 복제본과 CDC도 원천 비용이 0이 아니며 실제 측정으로 판단한다.

## 5. API 자동 생성의 산출물 예

ASH/AWR에서 발견한 “점포·일자 조건으로 매출 조회” 후보는 다음을 함께 생성한다.

- 추정 업무명, 근거 SQL 묶음, 데이터 출처와 관측 구간, 통계 누락 표시.
- SELECT 템플릿과 바인드 변수의 형식·범위·필수 조건. 문자열 조합 SQL 없음.
- 입력·출력 JSON Schema, OpenAPI, MCP tool 정의와 동일 계약 version/hash.
- 업무 의미의 확인 항목, 민감 컬럼, 서버 권한 필터, plan/range 테스트.
- 직접 조회/마트 후보의 이유, 검증 질문과 기대값, 위험·미확인 사항.

사용자에게 공개되는 API가 되려면 업무 의미·권한·실행계획·취소·부하·정합성 검증을 통과해야 한다. AST 파서가 읽기 전용 여부를 판정해도 함수 부작용까지 보장하지 못하므로 최소권한 DB계정·객체/함수 allowlist·DB 실행제한을 함께 적용한다.
