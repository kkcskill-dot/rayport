# 레이포트 초기 설계에서 1.0 구현까지

2026-11-08 사용자의 “1.0 버전까지 구현·테스트·개선·의문제기” 요청으로 기획 단계를 넘어 실제 서버·프론트·검증·패키징을 구현했다. 최신 구현 상태의 정본은 [1.0 릴리스 기록](DocsDeliveryRayportV1Release.md), 운영 절차는 [운영 문서](DocsDeliveryRayportV1Operations.md)다.

## 초기 제안과 실제 첫 릴리스

| 항목 | 초기 제안 | 현재 1.0 구현 범위 |
|---|---|---|
| 실행 구조 | Rust·React, APIC 실행 재사용 | 네 Rust crate·실제 React HTTP 연동·APIC 계약 어댑터 |
| 데이터 저장 | PostgreSQL 메타데이터/마트 권장 | 제한된 단일 노드 파일 스냅샷. SQL DB·분산 실행 미구현 |
| 질문 처리 | 업무 의미와 AI 도구 선택 | 등록 검색어 매칭, 명시 기간/점포. 범용 LLM 해석 미구현 |
| 발굴 | BeLoga/AWR/ASH 관측 근거 | 출처 있는 정규화 JSON 반입·SQL 정적 검증·후보 생성. AWR 원문 파서 미구현 |
| 마트 | 증분 갱신·정정·스케줄 | 완전 스냅샷 수동 반입·검증·버전 전환. CDC/자동 배치 미구현 |
| 권한 | 사내 OIDC와 점포 권한 정본 | 구성된 사용자 토큰·HttpOnly 세션·명시 점포 범위. 실제 SSO 미연동 |
| API/MCP | APIC/API/MCP 공통 계약 | 등록 도구 실행 경로·OpenAPI/MCP 메타데이터 export. 실제 MCP 프로토콜 서버 미등록 |
| 설치 | Linux 서버 배포 | native 패키징·설치/롤백 도구. 이 Mac 빌드와 Linux 인수는 별개 |

파일 저장소 선택은 초기 범위의 운영 단순화를 위한 구현 결정이다. 운영 원천과 별도로 보관하며 checksum·단일 writer 잠금·원자적 공개·실패 시 차단을 제공한다. 다중 노드·대량 집계로 확대할 때 저장 포트를 PostgreSQL/기존 DW/OLAP 어댑터로 교체해야 한다. 파일 저장의 최대 크기·쓰기 비용·백업 제한은 운영 문서에 명시한다.

## 검증 원칙

단위 규칙, 파일 장애 복구, in-process HTTP 라우터, JSDOM 화면, 패키지 설치를 검사한다. 포트를 열거나 로컬 DB/Testcontainers를 시작하지 않는다. 실제 고객 원천의 수치·권한·취소·부하는 이 테스트로 대체할 수 없다.

독립 검토에서 발견한 예산 우회·관측 출처 유실·지원하지 않는 질문의 완료·동기 파일 IO·평문 외부 bind·계약과 실행 불일치·UI 상태 전이 문제를 수정하고 해당 회귀 검증을 추가했다. 상세 증거와 수치는 릴리스 기록에 남긴다.

## 다음 외부 인수 조건

1. 실제 고객 APIC 계약/소스와 어댑터의 승인 SQL binding·실취소를 대조한다.
2. 실제 업무 정의·점포 권한 정본·원천 snapshot 기준을 확정한다.
3. 운영체제/CPU에 맞는 패키지를 빌드하고 TLS·인증·백업·복구를 인수한다.
4. ASH/AWR 사용권과 반입 범위를 확인하고 운영계 부하 총량을 측정한다.

이 조건이 확인되지 않은 상태에서 고객 운영계 인수 완료나 기존 MSTR 대체 완료를 주장하지 않는다.
